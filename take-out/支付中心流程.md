# 支付中心流程

1. 查库
   └─ 已是「待接单 + 已支付」→ 直接返回（业务幂等，不再付）

2. 未支付 → Redis 加锁（order:pay:lock:{orderId}）
   └─ 抢不到锁 → 说明别人正在付，拒绝连点

3. 锁内再查一次库
   └─ 可能刚被别人付成功了 → 仍直接返回成功

4. 状态校验
   └─ 必须是「待付款 + 未支付」，否则不可支付

5. CAS 更新
   └─ UPDATE ... WHERE id=? AND status=待付款 AND pay_status=未支付
   └─ 影响行数 = 1 → 成功（变成待接单 + 已支付）
   └─ 影响行数 = 0 → 再查一次：已付则当成功，否则失败

6. finally 解锁（只删自己的 token）

一句话：先看库 → 加锁防并发 → 锁内再看库 → CAS 只在理想状态才改库；Redis 管瞬时互斥，MySQL 管最终对不对。
