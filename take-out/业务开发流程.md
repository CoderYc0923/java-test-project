# 业务开发流程

面向本项目（Spring Boot 多模块 + MyBatis-Plus）的日常开发心智模型：什么时候改代码、什么时候改配置、什么时候加依赖。

---

## 1. 一句话先分清三层

| 层 | 放哪 | 干什么 |
|----|------|--------|
| **依赖（工具箱）** | 某模块 `pom.xml` | 引入第三方库 / 驱动 / Starter，让你能 `import` 并调用 |
| **配置（参数）** | `application.yml` 等 | 密钥、地址、超时、开关等**运行时可变**的值 |
| **业务代码** | `controller` / `service` / `mapper` / `util` | 用工具箱 + 配置完成具体功能 |

示例（JWT 登录）：

```text
pom 引入 jjwt        →  能写出 JwtUtil（生成/解析 Token）
yml 写 secret、ttl   →  运行时告诉 JwtUtil 用哪把钥匙、多久过期
Service/Controller   →  登录校验 + 发 Token + 拦截器验 Token
```

- **只写 yml、不加依赖**：Spring 不会自动会 JWT，配置只是字符串。
- **只加依赖、不写 yml**：库有了，密钥/过期只能写死在代码里，不灵活。
- **yml 不是依赖；依赖也不会自动读懂你的 `jwt.admin-secret-key`。**

---

## 2. 常规做一个业务功能的流程

```text
1. 定需求与接口：路径、入参、出参、要不要登录
2. 定数据：表是否已有 / 要不要改表；Entity、DTO、VO
3. 判断缺不缺能力（见第 3 节）
   - 缺 → 对应模块 pom 加依赖 → mvn install / IDE Reload
   - 不缺 → 跳过
4. 需要可配置项 → 写 application.yml，再用 @Value / @ConfigurationProperties 注入
5. 按分层写代码：Mapper → Service → Controller（工具类放 common）
6. 复用基建：Result、BusinessException、全局异常、（登录后）拦截器 / BaseContext
7. 安装依赖模块（改过 common/system 等时）并重启应用验证
8. 必要时补测试
```

对照本项目模块：

| 你改什么 | 优先落在 |
|----------|----------|
| 统一返回、异常、JWT 工具、ThreadLocal | `take-out-common` |
| 实体 / DTO / VO | `take-out-pojo` |
| Mapper、Service、查库逻辑 | `take-out-system` |
| 拦截器、WebMvc、全局异常扩展 | `take-out-framework` |
| 启动、Controller、`application.yml` | `take-out-admin` |

依赖方向（只向下）：`admin → framework → system → pojo → common`

---

## 3. 什么时候要加依赖？

### 3.1 需要加

引入**项目里还没有的能力**时，例如：

| 场景 | 典型依赖 |
|------|----------|
| 连 MySQL | `mysql-connector-j`、MyBatis-Plus Starter |
| JWT | `jjwt-api`、`jjwt-impl`、`jjwt-jackson` |
| Redis | `spring-boot-starter-data-redis` |
| 参数校验 | `spring-boot-starter-validation` |
| Excel | EasyExcel / POI |

**判断口诀：** 要 `import` 一个当前 classpath 里没有的包 → 就要在某个模块 `pom.xml` 里加依赖。

### 3.2 不需要加

| 场景 | 做法 |
|------|------|
| 新建 Controller / Service / Entity | 用已有 Spring / 业务代码即可 |
| 只增加自己的配置项 | 改 yml + 读取配置 |
| 写 DTO、常量、工具类、错误码 | 纯 Java 或已有依赖 |
| 模块互相调用 | 子模块 pom 依赖**本仓库其他模块**（如 admin → framework），不是再下一次相同三方库 |
| 改 SQL、改表、改业务判断 | 改库 / 改代码，一般不加新 jar |

### 3.3 依赖加在哪个模块？

```text
谁在编译期直接用到这个库，就加在谁的 pom；
多个模块都要用 → 放在偏底层的公共模块（如 common），上层通过模块依赖传递使用。
```

- JWT 工具在 `common` → jjwt 加在 `common`
- 只有 `system` 访问数据库 → MyBatis / 驱动加在 `system`
- `admin` 已依赖 `framework → system → common` → **admin 不必再写一遍 jjwt**

注意：

- 一个模块里只保留 **一个** `<dependencies>` 块，多个依赖放在同一块里。
- `jjwt-api` 一般不要 `runtime`；`jjwt-impl` / `jjwt-jackson` 常用 `runtime`。

## 4. 什么时候改 application.yml？

适合放配置的：

- 数据库地址、账号
- JWT 密钥、过期时间、Header 名
- 端口、日志级别、第三方 AK（后续）
- 环境相关开关

不适合当「依赖替代」的：

- 配了 `jwt.xxx` **不等于** 有了 JWT 能力，仍需 jjwt + 你的 `JwtUtil`

本项目示例：

```yaml
jwt:
  admin-secret-key: takeout-admin-secret-key-32bytes!!   # 建议 ≥ 32 字符（HS256）
  admin-ttl: 7200000
  admin-token-name: Authorization
```

代码侧由调用方读取后传入 `JwtUtil`（common 尽量不强绑 Spring，保持纯工具）。

## 5. 改完代码后如何让运行中的应用生效？

| 改动位置 | 建议操作 |
|----------|----------|
| 只改 `admin` 且用 IDE 热部署 | 视情况；不确定就重启 |
| 改了 `common` / `system` / `framework` | 先 `.\mvnw.cmd install -pl <模块> -DskipTests`（或根目录 `clean install`），再重启 admin |
| 只改 yml | 一般需要重启才会重新加载 |

推荐重启命令：

```powershell
# Ctrl+C 停掉当前进程后
.\mvnw.cmd spring-boot:run -pl take-out-admin
```

注意：`spring-boot:run` **不要**加 `-am`（会打到父工程）。改过依赖模块后若缺包，先 `install`。

## 6. 登录模块（认证）对照清单（当前阶段）

第一版目标：**员工登录 + JWT + 拦截器**，不做完整 RBAC。

| 步骤 | 内容 | 依赖？ | 配置？ |
|------|------|--------|--------|
| 1 | yml 写 jwt 参数 | 否 | 是 |
| 2 | common：jjwt + JwtUtil + BaseContext + 常量 | 是（jjwt） | 否（读配置在调用方） |
| 3 | pojo：LoginDTO / LoginVO | 否 | 否 |
| 4 | system：按用户名查库、校验密码 | 否（MyBatis 已有） | 否 |
| 5 | admin：登录接口发 Token | 否 | 使用 yml |
| 6 | framework：拦截器验 Token + 注册白名单 | 否 | 使用 yml 的 header 名 |

已有可复用基建：`Result`、`BusinessException`、`GlobalExceptionHandler`。

## 7. 常见误区

1. **以为配了 yml 就等于接入了某中间件** → 还要有对应 Starter/驱动 + 使用代码。  
2. **每个依赖单独包一层 `<dependencies>`** → POM 解析失败；应合并到一个块。  
3. **改了 common 不 install 不重启** → 运行中的进程仍用旧 jar，现象像「改了没生效」。  
4. **在 admin 重复引入 common 已有的三方库** → 通常多余；优先放底层模块。  
5. **密钥过短** → HS256 建议密钥足够长（实践中常 ≥ 32 字符）。

---

## 8. 速查口诀

```text
要 import 新包吗？     → 要 → 加 pom 依赖
只要改地址/密钥/开关？ → 改 yml
只写业务逻辑？         → 直接写代码，复用 Result/异常/拦截器
改了下层模块？         → install + 重启
```
